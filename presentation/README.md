### Slide 2: The Core Problem Statement
* **Curriculum Misalignment:** Students face uncertainty in identifying which programming tools and technologies employers actively require.
* **Subjective & Noisy Guidance:** Advice on social media or forums is subjective, unverified, and anecdotal.
* **Data Fragmentation:** Real-world recruitment listings contain noisy abbreviations, composite city names, and erratic job titles.
* **The "Fake Salary" Epidemic:** Many academic analytics projects attempt to fabricate or predict salaries on datasets where salary was never disclosed.

> **Speaker Notes:**  
> *"Every engineering undergraduate asks: 'What technologies should I focus on to become employable?' Relying on internet hearsay or outdated syllabi leads to wasted preparation time. Furthermore, recruitment data in India is messy and rarely includes published compensation. Our goal was to build a disciplined, reproducible engineering pipeline to replace guesswork with empirical evidence."*

---

### Slide 3: Main Project USP — Data-Driven Career Intelligence
* **Core Value:** Data-Driven Career Intelligence — empirical market validation replacing guesswork.
* **Four Fundamental Pillars:**
  1. **Empirical Evidence:** Frequency rankings across 12,000 postings guide high-ROI learning.
  2. **Heuristic Normalization:** Standardizes noisy variations (`py` → `Python`, `Bangalore` → `Bengaluru`).
  3. **Conservative Role Taxonomy:** 18 distinct role families preserve original titles while grouping cleanly.
  4. **Strict Data Ethics (Anti-Hallucination):** Transparently reports that salary data is unadvertised rather than training flawed synthetic ML models.

> **Speaker Notes:**  
> *"Our primary USP is Data-Driven Career Intelligence. We don't just dump charts; we normalize messy entities, categorize roles with a clear heuristic taxonomy, and maintain strict data ethics. When a dataset omits salary, we say so upfront, teaching responsible data science practices."*

### Slide 5: System Architecture & Technology Stack
* **Backend Tier:** Python 3.10+, Flask 3.x REST API, Gunicorn 22.x WSGI Server.
* **Data Processing Layer:** Pandas 2.x, NumPy, Regular Expressions (`re`), `@functools.lru_cache`.
* **Frontend Presentation:** Semantic HTML5, CSS3 Grid/Flexbox, Vanilla JavaScript (ES6+ Fetch Client).
* **Cloud Infrastructure:** Render Cloud Platform (Automated CI/CD from GitHub `main`).

> **Speaker Notes:**  
> *"We designed a lightweight, decoupled architecture. Instead of heavy JavaScript frontend frameworks that bloat page loads, we used vanilla HTML5, CSS Grid, and modern async Fetch. On the backend, Flask serves as a lightning-fast RESTful API, backed by Gunicorn and Python in-memory LRU caching."*

### Slide 6: Dataset Schema & Data Hygiene Audit
* **Dataset File:** `naukri_data_science_jobs_india.csv` (12,000 authentic Indian postings).
* **Core Dimensions:** `Job_Role`, `Company`, `Location`, `Job Experience`, `Skills/Description`.
* **Zero Exact Duplicates:** 12,000 verified rows retained with 100% data integrity.
* **Distinct Entities:** 6,563 raw titles, 3,507 companies, 822 raw locations normalized to 292 distinct cities.

> **Speaker Notes:**  
> *"Our dataset consists of 12,000 authentic job postings from Naukri.com across Indian technology sectors. Our data hygiene audit confirmed zero duplicate rows across all five dimensions. The data contains 6,563 distinct job title strings and 3,507 unique hiring organizations."*

---

### Slide 7: Normalization & Preprocessing Engine
* **Unicode NFKC Sanitization:** Cleans irregular spaces, non-breaking whitespaces, and symbols.
* **Deterministic Skill Aliasing:** Maps `py` → `Python`, `js` → `JavaScript`, `power-bi` → `Power BI`.
* **Multi-City Unrolling:** Splits compound entries (e.g., `Bangalore/Bengaluru, Pune`) and maps aliases.
* **18-Tier Conservative Role Taxonomy:** Classifies titles into standard families (*Data Engineer*, *Data Scientist*, *Data Analyst*, *Machine Learning Engineer*) while preserving original titles for search results.

> **Speaker Notes:**  
> *"Real-world data is inherently noisy. We built deterministic regex and dictionary-based cleaners. We map informal acronyms like 'py' to Python, unroll multi-city listings, and categorize raw titles into 18 recognized role families without losing the original employer title."*

---

### Slide 8: In-Memory Caching & Performance (<15ms)
* **The Performance Challenge:** Repeatedly filtering and aggregating 12,000 records on every HTTP request creates server lag.
* **The LRU Cache Solution:** Used `@functools.lru_cache(maxsize=1)` to store the cleaned Pandas DataFrame in RAM.
* **Measured Response Time:** Analytical API queries resolve in **under 15 milliseconds**.

> **Speaker Notes:**  
> *"To ensure a snappy user experience on cloud hosting, we implemented Python's LRU caching. The dataset is parsed, cleaned, and cached in RAM on server startup. As a result, API responses execute in under 15 milliseconds, even under concurrent requests."*

### Slide 13: Salary Transparency & Data Ethics Policy
* **Source Reality:** 100% of records in the provided Naukri dataset omit disclosed numerical compensation.
* **The Ethical Dilemma:** Many student projects train synthetic regression models that hallucinate fake salaries.
* **Our Policy (Anti-Hallucination):** Transparently exposes `/api/salary` and an in-app banner educating students that compensation is unadvertised in Indian job listings.

> **Speaker Notes:**  
> *"In data science, ethics and transparency are paramount. 100% of our source records lacked published salary numbers. Rather than fabricating predictions using ungrounded machine learning, we chose academic honesty by explicitly disclosing salary unavailability. This is a core feature, not a bug."*
